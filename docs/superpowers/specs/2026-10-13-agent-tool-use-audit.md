# Nalu agent and tool-use audit (2026-10-13)

Read-only audit of the Wave mid-turn tool loop, the structured-output turns, and the retry path. The audit covers `ai` 6.0.158 and `@ai-sdk/openai-compatible` 2.0.41 over Cerebras `gpt-oss-120b`. Line numbers refer to `main` at `9454f93`.

## 1. Summary

**Verdict.** The loop design is sound and conservative. It has a bounded loop, staging-only tools, closure-scoped lookups, flat tool schemas, and a byte-stable Context. Keep all of these. The gaps are at the edges: how a failed attempt is replayed, how an abnormal loop end is handled, and steering that the Harness could do deterministically but currently leaves to the prompt.

**Top 3 changes.**

1. **Fix #140.** Persist a failed tool-turn attempt as the prose the learner saw, cut at the JSON leak. Today it is a JSON envelope.
2. **Fail the attempt on a mid-loop transport error.** Today a Step-2+ failure can save a partial Turn.
3. **Move the grading-coverage check into the loop.** Bind the answered ids into `recordComprehensionSignals`, so a miss is fixed in-loop instead of by a whole-Turn retry. Force the call with `toolChoice` only after a probe shows that Cerebras honours it on gpt-oss.

## 3. Issue #140

### How the reference designs replay a rejected attempt

**Pydantic AI (v2.55.0).** There are two paths, and both keep the failure in history in its native shape.

- **Tool-level failure.** A tool, or its argument validation, raises `ModelRetry`. That becomes a `RetryPromptPart`. The failed `ToolCallPart` was already committed to history before the tool ran (`_agent_graph.py`, `_append_response`). The retry is sent as the **tool result for the same `tool_call_id`**: `role='tool'`, with the content `<message>\n\nFix the errors and try again.` (`messages.py` `RetryPromptPart.model_response`; `models/openai.py`). Retries are counted per tool. Running out raises `UnexpectedModelBehavior` (https://pydantic.dev/docs/ai/tools-toolsets/tools-advanced/#tool-retries).
- **Output-level failure.** An `@agent.output_validator` raises `ModelRetry`. For text, native or prompted output, the rejected response stays in history. Then a **user message** follows: `Validation feedback:\n<message>\n\nFix the errors and try again.` It uses one unit of a run-wide output budget, which defaults to 1 (https://pydantic.dev/docs/ai/core-concepts/output/#output-validator-functions). For tool output, the feedback is a tool result for the output call.
- Source for both: https://github.com/pydantic/pydantic-ai/blob/v2.55.0/pydantic_ai_slim/pydantic_ai/ (`messages.py`, `_agent_graph.py`, `_output.py`, `models/openai.py`).

**Mapping to Nalu.** Nalu's in-loop path already matches the tool-level path: `superRefine` directives and refusal results answer the same call id. Nalu's post-loop gate is the output-validator analogue. Its retry differs in two ways. It restarts with a fresh agent and collector instead of continuing the run. And it replays the failure as a **new serialisation**, the `{text, steps}` envelope, not as what the model produced. For this model the restart is right (section 5). The serialisation is the bug.

**AI SDK v6.** There is no built-in post-loop retry. It has three in-loop mechanisms:

- An invalid tool input or a thrown `execute` becomes a `tool-error` part. The next step sends it to the model as a `tool` message with `output: {type:'error-text', value: <message>}`, paired with the original tool call. The model fixes the call within the same run (`node_modules/ai/dist/index.mjs:3930-3973`; `node_modules/ai/docs/03-ai-sdk-core/15-tools-and-tool-calling.mdx:812-884`; probe finding 3).
- `experimental_repairToolCall` rewrites an invalid call before execution, "without requiring additional steps that pollute the message history". The re-ask example replays the failed call plus a tool result that holds the error (`15-tools-and-tool-calling.mdx:885-1012`).
- `Output.object` failure throws `NoObjectGeneratedError` with no automatic retry (`node_modules/ai/docs/03-ai-sdk-core/10-generating-structured-data.mdx`).

In both frameworks, the model sees its failed output in the shape it produced, followed by feedback. Neither wraps the failure in a new serialisation. Nalu's envelope invents an assistant message the model never wrote, and that message is JSON.

### Recommended fix

Change what is **written**, not how it is rendered. The replay-log rule says the bytes written are the bytes read back (`docs/ARCHITECTURE.md`, "Byte stability"). A render-time projection would add a parse-and-project special case to the pure renderer. It would also re-render existing terminal-exhaust rows.

1. `executeToolTurnStream` already sees every `text-delta` (`executeToolTurnStream.ts:205-207`). Accumulate the attempt's text across all steps. This is the learner-visible prose, the same string `streamWaveTurn` builds.
2. Move `findJsonProseLeakIndex` from `src/lib/course/waveMidTurnGate.ts` to `src/lib/turn/`. It is a property of any prose channel, not of Waves. `streamWaveTurn` then imports it from the new home.
3. Persist `failed_assistant_response.content` = that prose, cut at the leak index and trimmed. Persist no tool trail. Staged tool state is discarded per attempt, so replaying `recorded: N` tells the model that grading already happened, and the retry then fails the coverage gate. (This is a plausible second cause of exhaust. It is unverified.)
4. Keep the gate directives as they are. They already tell the model to redo the tool calls. Log the old envelope only under the dev-only debug gate (`src/lib/observability/gradingDebug.ts` pattern). Telemetry must not carry content.
5. Update `src/lib/turn/CLAUDE.md` and the `executeToolTurnStream` TSDoc, which describe the envelope. This lands with #139 (remove the unused `retryDirective` option), because both touch the same block.

Open edge: when the cut prose is empty (the empty-prose gate, or a leak at offset 0), the row holds `""`. Whether Cerebras accepts an empty assistant `content` is **unverified**. Cover it in the live test below.

## 4. Already good (do not "fix")

- **Flat tool schemas.** `src/lib/course/waveTurnTools.ts:23-66`, `:163-191`. `anyOf`/null unions dropped gpt-oss validity from about 95% to about 44% (`docs/status/2026-07-06-tool-call-probe-verdict.md`, runs 5-6). Note: the sample was 2×20 trials per arm. The gap is large enough to trust.
- **Wire/validator split.** `toToolInputSchema` with `stripNullsDeep` (`src/lib/llm/toCerebrasJsonSchema.ts:129-154`). It absorbs strict-mode-style `null`s without putting unions on the wire.
- **In-loop correction, Pydantic `ModelRetry` style.** `superRefine` directives come back as tool errors (`waveTurnTools.ts:80-133`, `:193-212`). Refusals are results, not throws: one questionnaire per Turn, first grading stands (`waveTurnTools.ts:255-301`), and the lookup returns `notFound` (`src/lib/agents/waveLookupTools.ts:68-70`). This matches Anthropic's advice to return actionable errors (https://www.anthropic.com/engineering/writing-tools-for-agents).
- **Deps by closure, the `RunContext` analogue.** `courseId` is bound by closure, never taken from model input (`waveLookupTools.ts:9-26`, `src/lib/agents/waveMidTurnAgent.ts:62-64`). A fresh agent and collector are built per attempt (`src/lib/course/streamWaveTurn.ts:98-111`).
- **The harness owns the score.** Emission tools only stage (`waveTurnTools.ts:253-255`). XP is per-probe and deterministic, and SM-2 changes only at Wave close (`applyAssessmentGrading.ts:56-61`). The model sees no XP.
- **Bounded loop.** `stepCountIs(LLM.maxToolSteps)` (`waveMidTurnAgent.ts:72`), and `isLoopFinished` is banned (`src/lib/agents/CLAUDE.md`). The AI SDK docs warn that `isLoopFinished` "could potentially run indefinitely" (`node_modules/ai/docs/03-agents/04-loop-control.mdx`).
- **Answer-key redaction, four layers.** Allowlist forwarding (`streamWaveTurn.ts:181-183`, `:212`); `tool-input-delta` dropped; questionnaire inputs and invalid-call inputs redacted (`:218-238`, `:269-286`); the text channel cut at an unfenced line-start `{` (`:128-149`, `src/lib/turn/findJsonProseLeakIndex.ts`; mid-line JSON too since #156). This is stricter than the SDK default `toUIMessageStream`, which would forward the input deltas.
- **Byte-stable instructions.** The agent's `instructions` are the same render as `renderContext(...).system`, and the dispatcher drops its own system message (`waveMidTurnAgent.ts:65-67`, `executeToolTurnStream.ts:197-200`). v7 now rejects system messages in `messages` by default, so Nalu already complies.
- **Recovered Turns render byte-identically.** The retry filter in `renderContext.ts:112-135` ensures this.
- **Per-step pacing and accounting.** `prepareStep` takes a rate-limit slot per Step, and `onStepFinish` feeds headers and usage (`waveMidTurnAgent.ts:77-88`).
- **Telemetry carries no learner content.** `recordInputs`/`recordOutputs` are pinned false (`src/lib/llm/CLAUDE.md`).
- **Structured turns use strict `json_schema` plus a Zod re-check.** Refines are included (`src/lib/llm/generate.ts:112-135`). openai-compatible sends `strict: true` by default (`dist/index.mjs:481, 521`). Keeping the close turn separate from the tool loop is required: gpt-oss-120b "rejects requests containing both" tools and `response_format` (https://inference-docs.cerebras.ai/resources/openai#unsupported-parameter-combinations).
- **Prose retry directives.** Zod issues are flattened to `- field path: message` bullets (`src/lib/turn/retryDirective.ts:39-60`). This is the same shape as Pydantic AI's retry prompt (section 3).
- **Parallel tool calls are safe.** Cerebras defaults `parallel_tool_calls` to true. Each staging `execute` checks and mutates the collector with no `await` in between, so concurrent calls in one step cannot race (`waveTurnTools.ts:255-299`).

## 5. Not recommended

- **Any tool that writes XP, SM-2, tier, or progression,** or that shows XP to the model. It breaks "the harness owns the score" (`AGENTS.md`).
- **Per-step `activeTools` or removing tools to stop repeat calls.** Tool definitions sit in the cached prefix on Cerebras ("tool schemas must stay identical", https://inference-docs.cerebras.ai/capabilities/prompt-caching) and on OpenAI. Use in-tool refusals (as now) or `tool_choice`.
- **History compression or summarising in `prepareStep`** (AI SDK "Context Management"), or Pydantic `history_processors` (in v2, the `ProcessHistory` capability). Pydantic's own docs warn that a mutated prefix means "the next request re-writes the entire prompt prefix at full input price" (https://pydantic.dev/docs/ai/core-concepts/message-history/). It breaks the append-only, byte-stable Context. A Wave's Context is small (about 4-6k input tokens per step in the A/B), so nothing needs trimming.
- **Continuing a failed attempt in-run, Pydantic output-validator style,** by keeping its staged tool calls and leaked text. It conflicts with the fresh-collector rule, keeps the JSON example in history, and would leave tool-kind rows in a recovered Turn, which breaks the render invariant.
- **`experimental_repairToolCall`.** In-loop `tool-error` feedback already self-corrected in every observed case (probe finding 3). Repair adds a hidden LLM call and persists a call the model never emitted.
- **`strict: true` on the emission tools, for now.** Strict mode needs `additionalProperties: false` everywhere. Under OpenAI semantics it also needs every field required, with optional fields expressed as a null union, which is the measured crater shape. Constrained decoding may change that, but flat schemas already score 95-100%. Re-probe only if invalid calls show up in production.
- **A `done` tool with `toolChoice: 'required'`** (AI SDK "Forced Tool Calling"). Prose would move into tool input, which kills text streaming and makes redaction harder.
- **`Output.object` alongside tools on mid-turns.** Cerebras rejects tools and `response_format` together for gpt-oss-120b.
- **Hint-mode due injection.** It was measured, and the model does not pull the list unprompted (`docs/status/2026-07-11-due-injection-ab.md`).
- **Upgrading to AI SDK v7 now.** It brings renames (`stepCountIs`→`isStepCount`, `onStepFinish`→`onStepEnd`, `experimental_repairToolCall`→`repairToolCall`), `prepareStep` overrides that carry forward, Node 22+, and ESM-only. None of this fixes a Nalu problem (https://ai-sdk.dev/docs/migration-guides/migration-guide-7-0). Revisit when v6 patches stop.
- **Sending prior Turns' reasoning back.** OpenAI says to drop analysis after a final answer (F6 source). It would also make the persisted Context depend on hidden tokens.
