# src/lib/llm

Single LLM integration point for the entire application. Built on the Vercel AI SDK v6 (`ai` + `@ai-sdk/openai-compatible`). Runtime `ai` imports belong in this directory and in `src/lib/agents/`. Lint exempts both and warns everywhere else. Current exceptions outside them keep their warnings: `tool()` in `src/lib/course/waveTurnTools.ts`, `NoObjectGeneratedError` in `src/lib/turn/`, and the UI-stream helpers in the wave-turn route and `src/hooks/useWaveTurnChat.ts`.

- `provider.ts` is the only swap-point for the underlying model. Env-driven (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). Switching providers is a one-line change here.
- Prompt cache key: `llmProviderOptions(promptCacheKey)` sends `reasoning_effort` and `prompt_cache_key` on every call. The key is the Context's id. A Wave's mid-turns and close send the wave id; scoping sends the scoping pass id. `executeTurn` passes `parent.id`; `buildWaveMidTurnAgent` takes `waveId`. Both parameters are required, so no call site can forget the key. Cerebras routes calls with one key to one prompt cache (#146). The key is an opaque id: never build it from learner content, and never share one across Contexts. The adapter spreads keys it does not know into the body as is, so the key is written snake_case. `provider.test.ts` pins the wire body. The key buys cache hits and latency only; cached input bills at the full rate.
- `generate.ts` wraps the SDK: `generateChat` (→ `generateText`) for every blocking LLM call. When `responseSchema` is supplied, the call uses `output: Output.object({ schema: toOutputSchema(...) })` — the SDK sets the strict `json_schema` `response_format` on the wire (Cerebras-cleaned bytes preserved) and Zod-validates the response (refines included) before returning `parsed`. Parse/validation failure throws the SDK's `NoObjectGeneratedError`; `executeTurn` converts it to `ValidationGateFailure`. Applies `tuning.LLM` defaults; forwards `usage`.
- `cerebrasToolLoopPrepareStep.ts` — shared per-step `prepareStep` for tool loops (fast-lane pacing + assistant `reasoning`-part strip); consumed by the `ToolLoopAgent` definitions in `src/lib/agents/`, which pair it with an `onStepFinish` recording rate-limit headers and usage. Tool-loop DISPATCH lives there + `src/lib/turn/executeToolTurnStream.ts`, not here.
- Structured calls are validated by the SDK against the supplied Zod schema before returning; transport retries are bounded by `LLM.maxRetries`.
- Output cap: tool-loop agents cap each Step at `LLM.maxToolStepOutputTokens` (sent as `max_tokens`, reasoning included), and a cut-off Step fails its attempt (#181). `generateChat` sets no cap on purpose: structured Steps run longer, and a cut inside reasoning leaves no text, so the SDK throws `NoOutputGeneratedError` and the Turn fails with no retry. The `tuning.ts` TSDoc holds the sizing data.
- `toolErrorText.ts` — the text the SDK sends the model for a tool error (`getErrorMessage`). `src/lib/turn/toolStepRows.ts` persists it, so the replayed `error-text` matches the loop's bytes (#147).
- `telemetry.ts` — env-gated (`LLM_TELEMETRY=true`) OTel spans on every LLM call, stage-labelled via `functionId`; `recordInputs`/`recordOutputs` are pinned FALSE (learner content stays out of traces — never weaken). Those flags do not cover a failed call's error text, which can quote model output or provider text, so `llmTelemetry` also passes a wrapping `tracer`. Its spans keep the error's class name (`safeErrorName`, `src/lib/security/`) and the ERROR status code, and drop the message and stack (#204). A new LLM call site must pass `llmTelemetry()`, or its spans skip the wrapper. `src/instrumentation.ts` registers the OTel SDK; spans export nowhere until an OTLP endpoint is configured (recipe: "Observability" in `docs/DEPLOY.md`).
- DevTools: `provider.ts` wraps the model with `devToolsMiddleware()` ONLY under `NODE_ENV=development` + `LLM_DEVTOOLS=1` (double gate — never in production; capture includes grading keys). `just dev-devtools` to capture, `just llm-devtools` for the viewer; data lands in gitignored `.devtools/`. Keep `@ai-sdk/devtools` on its 0.0.x line (npm tag `ai-v6`): 1.x pulls in `ai` v7.
- Token usage is returned on every call — propagate it, don't drop it.
- After every Step, call `recordStepFinished(headers, usage)` (`recordStepFinished.ts`). It feeds the rate limiter and the cost tally in one call. `generateChat` and each agent's `onStepFinish` call it, including on validation failure, since Cerebras bills that Step too. A new LLM call site must call it as well.
- Cost tally: `usageCost.ts` holds the pure math (`calculateUsageCostUsd`, `sumUsage`), priced by `CEREBRAS_PRICING` in `tuning.ts`. Cached input is NOT discounted; Cerebras bills it at the full rate. `runUsageTally.ts` keeps the running total in module state; its TSDoc names what the total spans. In production and live smoke it prints a cumulative `[llm-usage]` stderr line after each Step. `just smoke` prints one run total at the end (`src/lib/testing/smokeUsageTotal.*`). Streamed usage needs `includeUsage: true` in `provider.ts`. Cost never reaches the LLM.

## Render contract

- `renderContext.ts` is pure: same `(seed, messages)` → byte-identical
  output. The cache prefix is preserved when rows are appended. Tests
  assert both invariants — never weaken them.
- `renderContext` applies a per-turn retry filter: rows are grouped by `turn_index`; within a group containing an `assistant_response`, any `failed_assistant_response` + `harness_retry_directive` rows are dropped (they were intermediate retry exhaust). Terminal-exhaust groups (no `assistant_response`) keep every row so the model can see the failure context. This preserves cache-prefix stability — a recovered turn renders to the same bytes as a non-retry turn.
- The model→harness protocol is JSON and tool calls, never XML tags. Validation gates live in `src/lib/turn/` (`validationGateFailure.ts`); response schemas live in `src/lib/prompts/`.
