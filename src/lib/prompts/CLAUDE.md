# src/lib/prompts

Home for LLM prompt text. Prompt text belongs in this directory; the last bullet lists the current exceptions.

- Every renderer is a pure function: typed params in, string out. No side effects, no DB calls.
- Scoping is one append-only conversation. `renderScopingSystem` (in `scoping.ts`) emits the single `role: system` message: the role block only. Per-stage instructions live in each stage schema's `.describe()` annotations. Each later scoping turn appends user/assistant messages via `renderStageEnvelope` to keep the cache prefix byte-stable.
- Teaching prompts are assembled fresh (new `role: system`), static-first / dynamic-last.
- Use XML tags for structured sections. Avoid guessable tag names (`<system>`, `<instructions>`).
- Escape untrusted text before it enters a prompt. `renderStageEnvelope` escapes scoping input with `escapeXmlText`. Wave learner replies are wrapped by `sanitiseUserInput` upstream, in `src/lib/course/buildLearnerInput.ts`. The teaching and scoping system prompts both end their `<role>` with a Security block; keep the two in step. It names the tags that wrap learner text as data, and the Harness tags in user messages (`<stage>`, `<turns_remaining>`, `<concepts_for_next_wave>`, `<harness_feedback>`) as instructions to follow. "In user messages" matters: a Harness tag echoed in an assistant or tool row is not trusted. A new learner or Harness tag goes into the block for its phase. The block is safe only because learner text is always escaped: `src/lib/security/harnessTagForge.test.ts` sends a forged `<harness_feedback>` down every learner path (issue #123).
- Structured output: every LLM-facing schema (clarify, framework, baseline, grading) is a Zod schema with `.describe()` on each field. Every model receives those descriptions on the wire via `response_format` (the strict `json_schema` payload). Cross-field invariants live in `.refine` / `.superRefine`; refine messages are engineered as teacher-style retry directives so `executeTurn` can route them back to the model on `ValidationGateFailure`. `executeTurn` builds that directive with `buildRetryDirective`, which re-attaches the schema inline (`<response_schema>`) on that failure path only.
- Rubrics: a graded free-text question (baseline, Wave quiz) needs a rubric stating what a correct answer contains. `isPlaceholderRubric` in `questionnaire.ts` is the one rule: shorter than `QUESTIONNAIRE.rubricMinChars`, or opening with "no grading", the shape of clarify's `UNGRADED_RUBRIC`. The match is anchored, so "piano grading" mid-sentence passes. `baseline.ts` and the quiz tool in `src/lib/course/waveTurnTools.ts` reject it with `placeholderRubricDirective`, and render `GRADED_RUBRIC_RULE` (floor included) in their wire descriptions. The shared `questionSchema` rubric description stays neutral, and only clarify's own description names the placeholder. Keep examples like it off the shared schema: graded stages copy them (issue #22). MC rubrics stay unchecked. A typed answer to an MC question is graded against Harness data instead: the options, the correct key and `typedMcGradingRule` (issue #149). `src/lib/course/CLAUDE.md` names the two envelopes that carry them.
- `baseline.ts` renders the count rule per call: an exact total, the per-tier count, and the in-scope tier list. The per-tier count derives from the scope size (`BASELINE` in `tuning.ts`), so every legal scope lands in 7–9. The schema enforces only the total and tier membership, not per-tier counts.
- `closeTurn.ts` exports the shared `makeCloseTurnBaseSchema` used by scoping-close and wave-end. The scoping close uses it as is; `scopingClose.ts` holds only its stage envelope. The Wave close extends it in `waveClose.ts`. The model never picks the starting tier: `determineStartingTier` (`src/lib/scoring/`) computes it (issue #94). Wire descriptions use learner-facing vocab (`lesson`, `level`).
- `teaching.ts`'s `<due_for_review>` block obeys `WAVE.dueReviewInjection` ("full" | "hint"): hint mode replaces the list with a getDueConcepts nudge. Default is "full" and stays so: the 2026-07-11 live A/B (docs/status/) showed the model does not call the lookup unprompted. The output contract's lookup lines (`LOOKUP_LINES`) follow the same flag. Only hint mode names getDueConcepts, because only hint mode's agent offers it. Full mode drops the tool and never names it: the redundant call cost a Step and ~2k input tokens (issue #144, audit F4). Its block still leads with a review cue (`FULL_DUE_CUE`) that names no tool.
- `renderTeachingSystem` declares one output contract for the whole Wave: mid-turn prose is plain text, structured actions are tool calls, and the close turn answers in single JSON. Mid and close turns share the prompt, so the provider cache prefix survives mid→close.
- Mid-turn order: tool calls first, then the message. gpt-oss's harmony format ends the turn with the learner-facing message, so "call the tool after your prose" pushed the model to write the call as JSON text. Every place that states the order agrees: the output contract, the `presentQuestionnaire` description in `src/lib/course/waveTurnTools.ts`, the gate directives in `src/lib/course/waveMidTurnGate.ts`, the tool probe's description and system prompt in `scripts/probe-model.ts`, and the mid-Wave output contract in `docs/PRD.md`. Live A/B on Wave Turn 1, 2026-10-14, 20 single Steps per arm: JSON-text quizzes 8 → 0, quiz calls 11 → 20. Keep them in step.
- Exceptions to "prompt text lives here": the FLAT tool input schemas in `src/lib/course/waveTurnTools.ts` carry their own wire `.describe()`s and superRefine retry directives (the tool-channel analogue of schema descriptions). The same file holds the grading tool's result text: the repeat-signal refusal and the ungraded-answers nudge (issue #144). Single-JSON response schemas remain the contract for scoping and close turns. Model-facing text also lives in `src/lib/agents/waveLookupTools.ts` (tool descriptions), `src/lib/course/waveMidTurnGate.ts` (gate retry directives), `src/lib/turn/retryDirective.ts` (schema retry directives), `src/lib/course/buildLearnerInput.ts` (learner envelopes), and `src/lib/spaced-repetition/scheduler.ts` (`<concepts_for_next_wave>`).
