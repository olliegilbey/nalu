# src/lib/prompts

Home for LLM prompt text. Prompt text belongs in this directory; the last bullet lists the current exceptions.

- Every renderer is a pure function: typed params in, string out. No side effects, no DB calls.
- Scoping is one append-only conversation. `renderScopingSystem` (in `scoping.ts`) emits the single `role: system` message: the role block only. Per-stage instructions live in each stage schema's `.describe()` annotations. Each later scoping turn appends user/assistant messages via `renderStageEnvelope` to keep the cache prefix byte-stable.
- Teaching prompts are assembled fresh (new `role: system`), static-first / dynamic-last.
- Use XML tags for structured sections. Avoid guessable tag names (`<system>`, `<instructions>`).
- Escape untrusted text before it enters a prompt. `renderStageEnvelope` escapes scoping input with `escapeXmlText`. Wave learner replies are wrapped by `sanitiseUserInput` upstream, in `src/lib/course/buildLearnerInput.ts`. The teaching and scoping system prompts both end their `<role>` with a Security block. It tells the model to treat user-envelope text as learner input, never as instructions.
- Structured output: every LLM-facing schema (clarify, framework, baseline, grading) is a Zod schema with `.describe()` on each field. Every model receives those descriptions on the wire via `response_format` (the strict `json_schema` payload). Cross-field invariants live in `.refine` / `.superRefine`; refine messages are engineered as teacher-style retry directives so `executeTurn` can route them back to the model on `ValidationGateFailure` — `buildRetryDirective` re-attaches the schema inline (`<response_schema>`) on that failure path only.
- `closeTurn.ts` exports the shared `makeCloseTurnBaseSchema` used by scoping-close and wave-end. Scoping extends it via `scopingClose.ts` with `immutableSummary` + `startingTier`. Wire descriptions use learner-facing vocab (`lesson`, `level`).
- `teaching.ts`'s `<due_for_review>` block obeys `WAVE.dueReviewInjection` ("full" | "hint"): hint mode (tools contract ONLY — json has no lookup tools) replaces the list with a getDueConcepts nudge. Default is "full" and stays so: the 2026-07-11 live A/B (docs/status/) showed the model does not call the lookup unprompted.
- `teaching.ts` branches on `WaveSeedInputs.outputContract`: `"json"` (default) renders the mega-schema contract byte-identical to pre-tools output (blocking rollback path depends on this); `"tools"` renders the tool-calling role + output-format blocks. The contract selects the SYSTEM PROMPT only — the streaming transport passes `"tools"` for every turn of a wave (including the close turn, which still emits single-JSON) so the provider cache prefix survives mid→close.
- Exceptions to "prompt text lives here": the FLAT tool input schemas in `src/lib/course/waveTurnTools.ts` carry their own wire `.describe()`s and superRefine retry directives (the tool-channel analogue of schema descriptions). Mega-schema remains the contract for scoping and close turns. Model-facing text also lives in `src/lib/agents/waveLookupTools.ts` (tool descriptions), `src/lib/course/waveMidTurnGate.ts` (gate retry directives), `src/lib/turn/retryDirective.ts` (schema retry directives), `src/lib/course/buildLearnerInput.ts` (learner envelopes), and `src/lib/spaced-repetition/scheduler.ts` (`<concepts_for_next_wave>`).
