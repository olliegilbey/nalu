# src/lib/course

Scoping and Wave turn code, plus the pure helpers and state readers it shares. Each LLM-calling entry file wraps one Turn.

- Each scoping function: validate course state → run `executeTurn` with `responseSchema` (no translator helpers, no parser closures) → persist the wire shape directly to `courses.{column}` → return typed payload + `nextStage`.
- Untrusted scoping input reaches the prompt envelope via `renderStageEnvelope`, which XML-escapes. Wave learner input goes through `buildLearnerInput`, which wraps free text in `sanitiseUserInput`.
- Routers (`src/server/routers/`) and the wave-turn route call these functions; the client sequences scoping via `nextStage`. UI imports only client-safe pure helpers and types from here (`adaptQuestionnaire`, `shape*Answers`, `formatComposerAnswers`, `parseQuestionnaireBuffer`, `derive*ChatEntries`, `deriveActiveQuestionnaire`, `deriveTurnResultEffects`). The hooks keep only React state and side-effects; Wave-state decisions live in these helpers.
- `submitBaseline` closes scoping: mechanical MC grading first, then one append-only `executeTurn` against `makeScopingCloseSchema` (extends the shared `makeCloseTurnBaseSchema`). `persistScopingClose` then widens the JSONB, upserts concepts at default (untaught) SM-2, opens Wave 1 from `seedSource.scoping_handoff.blueprint`, seeds the assistant `openingText`, flips status to `active`, and bumps `totalXp` — one transaction.
- `closeGradingDebug.ts` writes issue #22 `[grading-debug]` lines at both close paths. It is a no-op unless `LLM_DEBUG_GRADINGS` is on (gate in `src/lib/observability/`). It never throws: it runs after the Turn's rows are saved.
- Wave turns have dual transports over one spine: `prepareWaveTurn` (guards + learner input) and `persistWaveMidTurn`/`executeWaveClose` (persistence) are shared by `submitWaveTurn` (blocking, tRPC `wave.submitTurn` — rollback path) and `streamWaveTurn` (UI message stream, consumed by the route handler under `src/app/api/course/`). Behavior must stay identical; fix the shared pieces, not one transport.
- Streamed mid-turns emit structure via the TOOL channel, not the mega-schema: `streamWaveTurn` runs `executeToolTurnStream` with a fresh agent per attempt (`buildWaveMidTurnAgent` in `src/lib/agents/` — emission tools + one `WaveTurnCollector` + read-only lookup tools, courseId closure-scoped) and the post-loop gate `waveMidTurnGate.ts`. Emission executes are STAGING ONLY (collector mutation — no DB, XP, or SM-2); `recordComprehensionSignals` stages one signal per `questionId` per turn and refuses later ones in its result, so the first grading stands; lookup executes are read-only capped projections; `persistWaveMidTurn` drains the collector unchanged. The blocking transport keeps the mega-schema (`outputContract: "json"`) until issue #50 deletes both.
- Tool input schemas in `waveTurnTools.ts` are deliberately FLAT (wire + validator): `anyOf` unions on the tool wire crater gpt-oss-120b validity ~95%→~44% (probe verdict finding 2, reproduced live). Keep unions out of tool wire bytes; map flat→canonical in the executes. The `superRefine` directive strings are prompt-engineered — never paraphrase.
- Questionnaire secrets (`correct`, `freetextRubric`) must never reach the client pre-submission: `streamWaveTurn` allowlist-redacts forwarded questionnaire tool inputs, drops `tool-input-delta` chunks, AND cuts text-delta forwarding at an unfenced line-start `{` (`findJsonProseLeakIndex`) — a JSON-imitation attempt dumps the answer key into the TEXT channel, which no tool-chunk redaction touches. The static reload wire (`redactWaveChatLog`) enforces the same invariant: `correct` → `correctEnc`, `freetextRubric` dropped outright. Preserve all four on any forwarding or projection change.
