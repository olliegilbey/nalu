# src/lib/course

Scoping and Wave turn code, plus the pure helpers and state readers it shares. Each LLM-calling entry file wraps one Turn.

- Each scoping function: validate course state → run `executeTurn` with `responseSchema` and `responseSchemaName` (no translator helpers, no parser closures, no retry directive: `executeTurn` builds it) → persist the wire shape directly to `courses.{column}` → return typed payload + `nextStage`. The Wave close turn calls `executeTurn` the same way.
- Untrusted scoping input reaches the prompt envelope via `renderStageEnvelope`, which XML-escapes. Wave learner input goes through `buildLearnerInput`, which wraps free text in `sanitiseUserInput`.
- A typed answer to an MC question (no `matchOptionIndex` match) is graded as free text. Its rubric is unchecked, so the Harness attaches the options, the correct key and `typedMcGradingRule` after submit (issue #149). The Wave envelope (`buildLearnerInput`, mid and close turns) adds an `<mc_answer_key>` block with escaped options. The scoping close (`buildScopingCloseLearnerInput`) adds `mcAnswerKey` to that answer's JSON. The question type gates the key, not the client's `fromEscape`. The key reaches only the model's Context: `waves.chat_log` and `courses.baseline.responses` keep the raw text, so no client projection gains it.
- Routers (`src/server/routers/`) and the wave-turn route call these functions; the client sequences scoping via `nextStage`. UI imports only client-safe pure helpers and types from here (`adaptQuestionnaire`, `shape*Answers`, `formatComposerAnswers`, `questionnaireBuffer`, `questionnaireKey`, `derive*ChatEntries`, `deriveActiveQuestionnaire`, `deriveActiveScopingQuestionnaire`, `deriveTurnResultEffects`, `deriveStreamingTurn`, `deriveStrandedScopingTurn`, `hasScopingTurnLanded`, `selectComposerQuestionnaire`, `deriveComposerControls`, `deriveSendAction`, `deriveQuestionnaireAdvance`, `deriveMcXpAward`). The hooks keep only React state and side-effects; Wave, scoping and answer-card decisions live in these helpers.
- `deriveStrandedScopingTurn` rebuilds a failed scoping Turn's Retry after a reload (issue #103). `generateFramework` and `submitBaseline` save the learner's answers before the LLM call, so saved answers with no model output mean the Turn failed. The same state holds while the Turn is in flight, so callers skip the check while a Turn is pending. That gate is in-tab only: after a reload mid-Turn, or in a second tab, Retry can re-send while the original still runs. The server keeps that safe. `updateCourseScopingState` writes only while the course is in `scoping`, and `submitBaseline` replays the winner's payload when a concurrent close beats it.
- `submitBaseline` closes scoping: mechanical MC grading first, then one append-only `executeTurn` against `makeScopingCloseSchema` (extends the shared `makeCloseTurnBaseSchema`). `persistScopingClose` then widens the JSONB, closes the scoping pass, upserts concepts at default (untaught) SM-2, opens Wave 1 from `seedSource.scoping_handoff.blueprint`, seeds the assistant `openingText`, flips status to `active`, and bumps `totalXp` — one transaction.
- `closeGradingDebug.ts` writes issue #22 `[grading-debug]` lines at both close paths. It is a no-op unless `LLM_DEBUG_GRADINGS` is on (gate in `src/lib/observability/`). It never throws: it runs after the Turn's rows are saved.
- Every Wave turn runs through `streamWaveTurn` (UI message stream, called by the route handler under `src/app/api/course/`). It runs `prepareWaveTurn` (guards, bug_001 idempotency, pre-LLM learner entry), then dispatches: mid-turns persist through `persistWaveMidTurn`; the close turn runs `executeWaveClose`, a blocking `executeTurn` inside the stream.
- Mid-turns emit structure via the TOOL channel: `streamWaveTurn` runs `executeToolTurnStream` with a fresh agent per attempt (`buildWaveMidTurnAgent` in `src/lib/agents/` — emission tools + one `WaveTurnCollector` + read-only lookup tools, courseId closure-scoped) and the post-loop gate `waveMidTurnGate.ts`. Emission executes are STAGING ONLY (collector mutation — no DB, XP, or SM-2); `recordComprehensionSignals` stages one signal per `questionId` per turn and refuses later ones in its result, so the first grading stands; it also holds the turn's answered question ids by closure, and its result names any still ungraded (`stillUngraded`, `nextStep`), so the model completes a partial call in-loop (issue #144) — it never throws, and the post-loop gate stays the backstop for a Turn with no call at all; lookup executes are read-only capped projections; `persistWaveMidTurn` drains the collector unchanged.
- Tool input schemas in `waveTurnTools.ts` are deliberately FLAT (wire + validator): `anyOf` unions on the tool wire crater gpt-oss-120b validity ~95%→~44% (probe verdict finding 2, reproduced live). Keep unions out of tool wire bytes; map flat→canonical in the executes. The `superRefine` directive strings are prompt-engineered — never paraphrase.
- Questionnaire secrets (`correct`, `freetextRubric`) must never reach the client pre-submission: `streamWaveTurn` allowlist-redacts forwarded questionnaire tool inputs, drops `tool-input-delta` chunks, AND cuts text-delta forwarding at a JSON-opening `{` outside fences and backtick spans, at line start or mid-line before a quoted key (`findJsonProseLeakIndex` in `src/lib/turn/`, which also cuts a failed attempt's replayed prose; #156) — a JSON-imitation attempt dumps the answer key into the TEXT channel, which no tool-chunk redaction touches. Accepted prose persists whole, so the post-loop gate (`waveMidTurnGate.ts`) is the backstop. Its secret check is fence-blind: it fails any attempt whose prose uses the tool's field names as JSON keys (`"freetextRubric":`, or `"correct":` with `"conceptName":`). Its envelope check fails a balanced object with an envelope key outside code; the close turn's `nextUnitBlueprint` and `conceptUpdates`, and the blueprint's `openingText` and `plannedConcepts`, count too (#172). A dump under invented field names can still persist; a fenced dump can still stream live (#159). The static reload wire (`redactWaveChatLog`) enforces the same invariant: `correct` → `correctEnc`, `freetextRubric` dropped outright. Preserve all four on any forwarding or projection change. Separately, only `presentQuestionnaire` tool chunks cross the wire (`CLIENT_FORWARDED_TOOLS`, typed by `ClientForwardedToolName` in `src/lib/types/waveStream.ts`): lookup and grading-signal chunks have no client consumer and stay server-side (issue #59).
